TripBalancing Step 3 - Razorpay Production Audit
Date: 2026-08-24

Scope: payment security/production cleanup only. No UI redesign, pricing-plan redesign, Gemini changes, budget changes, or auth/RLS redesign.

Problems found and fixed:
1. Removed server mock Razorpay key fallback (rzp_test_mock_key_id).
2. Removed frontend hardcoded Razorpay test key fallback.
3. Payment create/verify endpoints now require a valid signed-in Supabase access token.
4. Browser-supplied payment amount is ignored. Plan prices are determined on the server.
5. Razorpay orders now bind planType + authenticated user ID/email in server-created order notes.
6. Verification uses HMAC signature checking with timingSafeEqual.
7. After signature verification, server fetches the authoritative Razorpay order and payment and validates order ownership, plan, currency, amount and payment status.
8. The browser can no longer upgrade a cheap valid order into another plan by changing planType during verification.
9. Added payment-id idempotency so replaying the same verified payment cannot repeatedly grant trip credits.
10. Entitlements are written to user_profiles by the server after successful verification. The frontend no longer writes a paid plan to the database itself.
11. Client UI uses the server-returned verified plan instead of trusting the locally selected plan.

Not removed:
- Admin 'send test email' sample Razorpay IDs remain because they are only dummy values for email-template testing, not checkout/payment fallbacks.
- USD -> INR order fallback remains because it is a currency/payment-method fallback using the same live Razorpay credentials, not Razorpay test mode.

Production environment required:
- RAZORPAY_KEY_ID = live key
- RAZORPAY_KEY_SECRET = matching live secret
- VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY configured
- SUPABASE_SERVICE_ROLE_KEY configured so verified server payments can update entitlements

Recommended live verification after deployment:
- successful INR purchase activates exactly the purchased plan
- cancelled/failed payment activates nothing
- replaying verify for the same payment does not add credits again
- logged-out user cannot create/verify a payment order
