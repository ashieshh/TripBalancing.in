TripBalancing Step 1 - Indian-origin flight pricing fix (2026-08-24)

Scope: flight pricing only. No UI, PDF, budget-category, payment, auth, or product-concept changes.

Root cause fixed:
- Travelpayouts/Aviasales Data API fare endpoints used by server.ts support USD/EUR/RUB.
- The project was requesting currency=inr. That can return no usable cached fare and push Indian-origin routes into the route-model fallback even when market fare data exists.

Changes:
1. server.ts now requests Aviasales cached fare data in USD while keeping market=in for Indian-market cache selection.
2. Returned per-traveler USD fare is converted to INR using TripBalancing's existing shared live FX table (getLiveCrossRate). If FX is unavailable, the existing INR fallback rate of 85 is used.
3. Removed the hidden +8% markup from cached Aviasales fares. A cached fare is now represented as the source fare converted to INR, then multiplied once by traveler count.
4. Existing exact-date -> month -> week -> grouped -> latest cache search sequence is preserved.
5. Existing route-model fallback remains unchanged when no usable market fare exists.

No destination-specific fare was hardcoded.
